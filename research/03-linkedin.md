# LinkedIn: تنزيل ملفات الفيديو عبر API مقابل التضمين

## القرار

**نعم، لدى LinkedIn واجهة رسمية تتيح الحصول على `downloadUrl` لفيديو عبر Videos API، لكن هذا ليس رابطًا عامًا للبحث عن أي فيديو أو تنزيله.** يتطلب ذلك تطبيقًا معتمدًا، مصادقة وصلاحيات مناسبة، ومعرّف فيديو يمكن للتطبيق الوصول إليه. تعرّف الوثائق `downloadUrl` بأنه رابط عام لتنزيل/عرض أصل الوسائط، وتعرض مثالًا لطلب `GET /rest/videos/{videoURN}` يعيد الرابط. لكن الوثائق لا تعد باسترجاع بايتات الملف الأصلي كما رفعها المستخدم: المثال عبارة عن مسار MP4 بترميز/دقة مشتقة (`mp4-720p-30fp-crf28`)، كما أن الرابط قد ينتهي أو يبطل عند تدوير مفاتيح التوقيع. [1]

### المحتوى الذي يملكه المستخدم أو الصفحة

الـ API موثق لإدارة أصول الفيديو التي يرفعها الشريك ويملكها عضو أو مؤسسة، ويعيد معرّف `video URN` عند الرفع. لاسترجاع منشورات عضو، تتطلب Posts API صلاحية `r_member_social` المقيدة والمتاحة للمستخدمين المعتمدين فقط؛ ولمنشورات مؤسسة تتطلب `r_organization_social` وأن يكون العضو مسؤولًا أو ذا دور نشر/إدارة محتوى مناسب في الصفحة. ويمكن أن يحوي سجل المنشور معرّف الفيديو الذي يُستخدم لاحقًا في Videos API. [1] [2]

توضح LinkedIn أن تطبيقات Marketing API تستخدم تفويض العضو عبر OAuth 2.0، وأن التطبيق لا يصل إلى موارد العضو قبل موافقته. لا تكفي موافقة OAuth وحدها: يلزم أيضًا اعتماد المنتج والصلاحيات المطلوبة وامتلاك دور الوصول المناسب للأصل. [3]

### المحتوى العام للآخرين

لا توثق هذه الواجهات طريقة لاكتشاف أو تنزيل فيديو أي منشور عام عشوائي. الاسترجاع بالـ API يبدأ بمعرّف مورد، وصلاحيات قراءة المنشورات محددة بحسب مالك المحتوى؛ كون المنشور عامًا لا يمنح تلقائيًا صلاحية تنزيل أصله. لذلك لا ينبغي اعتبار `downloadUrl` آلية تنزيل عامة للمحتوى العام، ولا ينبغي استنتاج إمكانية الوصول إلى فيديوهات الغير من نموذج الاستجابة وحده. [1] [2]

**التضمين مختلف عن التنزيل:** تتيح LinkedIn تضمين المنشورات العامة عبر خيار **Embed this post**، بما فيها منشورات الفيديو وخيار **Embed video only**. تقول صفحة المساعدة إن المنشورات التي شاركها المؤلف علنًا فقط قابلة للتضمين، وإن التضمين يُحذف إذا حذف المؤلف المنشور. هذا كود تضمين لمحتوى LinkedIn، وليس رابط ملف خام أو API لاستخراجه. [4] وتوثيق نشر المقالات يشرح إدراج كود المنشور، لا تنزيل ملف الفيديو. [5]

## الوصول والقيود العملية

- Community Management API منتج خاضع للمراجعة، وله **Development Tier** محدود و**Standard Tier** يتطلب ترقية وموافقة. تصف صفحة البرنامج الاستخدام المتاح بأنه للمؤسسات القانونية المسجلة ولأغراض تجارية، وتشترط معلومات مؤسسة موثقة وربط التطبيق بصفحة LinkedIn، كما تطلب في طلب Standard عرضًا مسجلًا للتطبيق ومراجعته. تختلف الحصص باختلاف الطبقة؛ تذكر الوثائق حدًا افتراضيًا للتطوير قدره 500 طلب لكل تطبيق و100 لكل عضو خلال 24 ساعة، مع تعطيل `BATCH_GET` في تلك الطبقة وفق دليل الانتقال. [6] [7]
- الصلاحيات ليست مفتوحة لجميع المطورين. `r_member_social` مغلقة/مقيدة؛ وتقول صفحة Community Management إن LinkedIn لا يقبل حاليًا طلبات جديدة لها بسبب قيود الموارد. وفي المقابل، `r_organization_social` مقيدة بأدوار صفحة المؤسسة. [2] [6]
- وثائق Videos API تذكر رفضًا بحالة 403 عند عدم كفاية الإذن، وتذكر صراحةً أن رفع فيديو بمالك مؤسسة يتطلب ADMIN أو DSC، وأن مالك فيديو العضو يجب أن يطابق العضو. هذه الشروط موثقة تحديدًا لعملية الرفع؛ لا أعممها وحدها على كل تفاصيل قراءة الفيديو. [1]
- `downloadUrl` قد لا يظهر إذا كان الأصل غير متاح أو فشل معالجته، وله حقل انتهاء صلاحية اختياري؛ حتى الرابط الذي لا يعرض موعد انتهاء قد يتوقف لاحقًا بسبب توقيعه. تعامل معه كرابط مؤقت، لا كعنوان دائم أو مصدر CDN ثابت. [1]
- يجب استخدام رؤوس الإصدار وRest.li المطلوبة في توثيق API، مع الالتزام بإصدارات Marketing API المدعومة ومواعيد إيقاف الإصدارات. [1] [2]

## الحقوق وسياسة الاستخدام

تقول اتفاقية المستخدم إن العضو يظل مالكًا لمحتواه الأصلي، لكنها تمنح LinkedIn ترخيصًا غير حصري لاستخدامه ضمن شروط الاتفاقية. وتسمح إعدادات الجمهور بإتاحة محتوى مختار علنًا أو تضمينه؛ لكن ذلك لا ينقل ملكية المحتوى ولا يمنح طرفًا ثالثًا حق نسخ ملف الفيديو أو إعادة توزيعه. وتحظر الاتفاقية كشط الخدمة أو نسخها، والتحايل على ضوابط الوصول، واستخدام أو توزيع محتوى مأخوذ من الخدمة دون موافقة مالكه. ينبغي لذلك تنزيل/إعادة استخدام فيديو يخص المستخدم نفسه أو المؤسسة صاحبة الصلاحية فقط، أو الحصول على إذن صاحب الحقوق والأساس القانوني اللازم قبل استخدام محتوى طرف آخر. [8]

## التوصية

إذا كان المطلوب أرشفة فيديو يملكه صاحب الحساب/الصفحة، احتفظ بالملف الأصلي خارج LinkedIn عند الرفع. وعند الحاجة إلى نسخة مستضافة، استخدم Videos API فقط بعد اعتماد المنتج والصلاحيات المناسبة، واستخرج `downloadUrl` لمعرّف فيديو مخوّل، ثم نزّل ضمن صلاحية الرابط وسجّل أن الناتج قد يكون نسخة معالجة لا الملف الأصلي. لمنشور عام يخص طرفًا آخر، استخدم ميزة التضمين الرسمية عند سماح المؤلف، ولا تعامل التضمين كرابط تنزيل. لا تستخدم كشط الصفحات أو التحايل على تسجيل الدخول أو CAPTCHA أو قيود الصلاحيات.
