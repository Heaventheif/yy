# تقرير موحّد: خدمة تنزيل تعمل على Vercel للمنصات الخمس

## 1. الملخص التنفيذي

تُظهر النتائج الموثقة أن المنصات الخمس لا تقدم «منزّلًا عامًا» يمكنه أخذ أي رابط عام واستخراج ملف فيديو خام بصورة مشروعة وموثوقة. القدرة الفعلية تختلف بين ثلاث حالات يجب فصلها في المنتج:

1. **تنزيل رسمي مدعوم ومصرّح به:** يحصل عندما يكون المستخدم مالكًا للمحتوى أو مفوّضًا عليه، وتتيح الواجهة الرسمية رابط ملف أو نقطة تنزيل ضمن الصلاحيات والخطة المطلوبة. ينطبق بوضوح على بعض مسارات **Vimeo**، وتنزيل **Twitch Clips** للمحررين المخولين، وروابط أصول محددة في **Snapchat Public Profile API**، و**LinkedIn** عند وجود فيديو مخوّل. كما توجد تنزيلات من واجهة المنتج نفسها في حالات محددة على Pinterest وVimeo وTwitch.
2. **عرض عبر embed/oEmbed أو مشغّل رسمي:** يعرض المنشور أو الفيديو داخل صفحة الخدمة، لكنه لا يسلّم ملفًا محليًا ولا يثبت حق تنزيله. ينطبق ذلك على Pinterest widgets، وSnapchat web embeds، وتضمين LinkedIn للمنشورات العامة، وVimeo oEmbed/iframe، وTwitch Player/iframe.
3. **استخراج غير موثوق أو تجاوز للقيود:** يشمل scraping، وفحص روابط مخفية أو CDN غير موثقة، وتجاوز تسجيل الدخول أو CAPTCHA أو OAuth أو صلاحيات المحتوى، واستخدام endpoint غير موثق. هذا المسار يجب رفضه، لأنه يخالف القيود الموثقة وقد يفشل تقنيًا عند انتهاء الروابط أو تغيير المنصة.

**التوصية الأساسية لخدمة Vercel:** لا تُبْنَ الخدمة على وعد «تنزيل أي فيديو من أي منصة». صمّمها كطبقة توجيه وصلاحيات: تتحقق من المنصة ونوع العملية، وتسمح فقط بمسارات رسمية تخص محتوى المستخدم أو محتوى لديه تفويض واضح، وتحوّل باقي الحالات إلى embed للعرض أو إلى رسالة رفض/طلب إذن. احتفظ بالملف الأصلي قبل رفعه عندما يكون المطلوب أرشفة ملف المستخدم؛ لا تعتمد على إعادة تنزيل المنصة لاستعادة الأصل.

> لا تستخلص المراجع المقدمة أن أي API مدفوعة أو مجانية إلا حيث ذُكر ذلك صراحة. وبوجه عام، «وجود API» لا يعني إتاحة تنزيل الفيديو أو إتاحة محتوى الغير.

## 3. تصنيف السلوك الذي يجب أن تلتزم به الخدمة

### أ. تنزيل مدعوم رسميًا

يُسمح به في المنتج فقط عندما تتوافر الشروط التالية، بحسب المنصة:

- **هوية وصلاحية قابلة للتحقق:** OAuth أو رمز وصول أو دور محرر/عضو أو مالك الحساب، لا مجرد كون الرابط عامًا.
- **نقطة API أو خيار منتج موثق:** يجب أن يعيد المسار رابط ملف أو يوضح طريقة التنزيل. لا يكفي وجود بيانات وصفية أو رابط مشاهدة.
- **نطاق المحتوى:** التنزيل محصور في أصول المستخدم أو الأصول التي يملك تفويضًا واضحًا لاستخدامها.
- **احترام قيود المنصة:** الخطة، قائمة السماح، الحدود، مدة صلاحية الرابط، إعدادات المالك، واشتراط تسجيل الدخول.
- **عدم تقديم وعد بالملف الأصلي:** بعض المنصات تعيد نسخة معالجة أو محوّلة، ولا تضمن الأصل المرفوع.

### ب. embed/oEmbed

التضمين هو بديل عرض، وليس تنزيلًا. ينبغي أن يوسم في الواجهة بوضوح مثل «عرض عبر المنصة» وألا يُحفظ الملف في تخزين الخدمة أو يُقدَّم كرابط تنزيل. وهو مناسب عندما:

- لا توجد صلاحية تنزيل موثقة.
- يريد المستخدم معاينة المحتوى دون استضافة نسخة منه.
- يسمح المؤلف/المنصة بتضمين منشور عام.

التضمين لا يبرر استخراج `src` الداخلي أو روابط CDN أو تحويل المشغل إلى ملف محلي.

### ج. استخراج غير موثوق أو تجاوز يجب رفضه

يجب رفض العمليات التي تطلب أو تتطلب:

- scraping أو جمعًا آليًا غير مصرح به.
- تجاوز تسجيل الدخول أو CAPTCHA أو ضوابط OAuth، أو استخدام جلسة/رمز لا يخص المستخدم.
- كشف روابط مخفية أو مؤقتة خارج endpoint الموثق، أو إعادة استخدامها بعد انتهاء صلاحيتها.
- تنزيل محتوى الغير لمجرد أنه عام، أو نسخ/إعادة توزيع المحتوى دون إذن.
- استعمال API للفيديو في اتجاه غير موثق: مثل تحويل API النشر/الرفع إلى آلية تنزيل، أو اعتبار رابط المشاهدة ملفًا قابلًا للتنزيل.

## 4. تحليل المنصات والتوصية التنفيذية

### 4.1 Pinterest

**ما تسمح به الوثائق:** API الرسمية تتيح قراءة بيانات Pins بصلاحيات OAuth. `GET Pin` مقيد بالـPins المملوكة لحساب العملية أو الموجودة على لوحة جماعية مشتركة معه؛ والـPins السرية تتطلب `pins:read_secret`. لا توثق API endpoint أو حقلًا للحصول على ملف فيديو خام أو رابط تنزيله. API الفيديو الموثقة تخص الرفع والنشر. في واجهة Pinterest، يمكن تنزيل بعض فيديوهات الشاشة الكاملة 9:16 فقط إذا فعّل صاحب المحتوى التنزيل، ويظهر اسم المستخدم كعلامة مائية.

**القيود التشغيلية:** تسجيل التطبيق يتطلب طلب Trial ومراجعة؛ يلزم OAuth وموافقة المستخدم على `boards:read` و`pins:read` للقراءة. ترقية Standard تتطلب مراجعة وعرضًا توضيحيًا. الحد العام للـTrial هو 1,000 طلب يوميًا لكل تطبيق. في Standard، الحد العام 100 طلب/ثانية لكل مستخدم وتطبيق، وحد `org_read` لجلب Pins هو 1,000/دقيقة لكل مستخدم وتطبيق؛ الحدود قابلة للتغيير. لا تذكر صفحات الوصول الرسمية المفحوصة رسوم API، لذلك لا يصح استنتاج أنها مدفوعة أو مجانية.

**قرار المنتج:**

- لملف يملكه المستخدم: استخدم الملف الأصلي الذي يرفعه المستخدم أو خيار التنزيل الرسمي إذا أتاحه Pinterest.
- لمحتوى عام: استخدم Pinterest widget للعرض فقط، أو اطلب إذنًا وملفًا من صاحب الحقوق.
- لا تبنِ مسار MP4 عامًا على Pinterest API، ولا تستخدم scraping أو روابط مخفية أو تجاوزات الوصول.
- شروط المطور تمنع جمع/مشاركة/بيع محتوى المستخدمين الآخرين كتطبيق غرضه الأساسي ذلك دون موافقة كتابية، وتحظر الوصول الآلي غير المصرح به. إرشادات المطور تطلب إرجاع Pins إلى مصدرها وعدم إعادة إنشاء Pins لتوزيعها.

**التصنيف:** تنزيل رسمي محدود من واجهة المنتج/محتوى مصرّح به؛ embed للعرض؛ استخراج MP4 العام غير موثق ويُرفض.

**مصادر:** [Pins list](https://developers.pinterest.com/docs/api/v5/pins-list/)، [Pins get](https://developers.pinterest.com/docs/api/v5/pins-get/)، [إنشاء Pin من صورة أو فيديو](https://help.pinterest.com/en/article/create-a-pin-from-an-image-or-video)، [Media create](https://developers.pinterest.com/docs/api/v5/media-create/)، [Widgets](https://developers.pinterest.com/docs/web-features/widgets/)، [Access tiers](https://developers.pinterest.com/docs/api-features/access-tiers/)، [Authentication](https://developers.pinterest.com/docs/getting-started/set-up-authentication-and-authorization/)، [Rate limits](https://developers.pinterest.com/docs/reference/rate-limits/)، [Developer guidelines](https://policy.pinterest.com/developer-guidelines).

### 4.2 Snapchat

**ما تسمح به الوثائق:** Public Profile API توثق `media_url` قابلًا للتنزيل ضمن أصول محددة، بما يشمل Spotlight وبعض Snaps. لكنها مقيدة بقائمة سماح، وتتطلب حساب أعمال وتطبيق OAuth ورمز وصول لكل طلب. النقاط العامة لا تتطلب تفويضًا فرديًا من صاحب الملف، لكنها تعرض بيانات محدودة؛ والبيانات المصرح بها تتطلب Creator OAuth أو مشاركة بيانات المنشئ.

لصاحب الحساب، تتيح Snapchat تنزيل Memories أو طلب My Data. My Data يتطلب تسجيل الدخول وطلب تصدير يدويًا، وقد يستغرق حتى سبعة أيام أو أكثر للطلبات الكبيرة، ولا يشمل بالضرورة بيانات لم تعد متاحة. لا تعني API النطاقية إتاحة كل فيديو عام أو خاص؛ يجب التحقق من الحقل الذي يعيده الرد ومن صلاحية التطبيق.

**قرار المنتج:**

- للأصول التي ترجعها Public Profile API: استخدم `media_url` كما ترجعها الواجهة، بعد استيفاء OAuth والإدراج في قائمة السماح واحترام حقوق الاستخدام.
- لملفات الحساب نفسه: استخدم Export في Memories أو My Data؛ لا تقدمه كتنزيل فوري مضمون داخل Vercel.
- استخدم web embeds للعرض فقط.
- لا تتجاوز تسجيل الدخول أو CAPTCHA أو قيود الوصول أو اشتراطات API، ولا تفترض أن كل فيديو عام قابل للتنزيل.

**التصنيف:** تنزيل رسمي محدود لأصول API المسموح بها أو تصدير صاحب الحساب؛ embed للعرض؛ الاستخراج خارج الأصول الراجعة أو خارج المسارات الموثقة يُرفض.

**مصادر:** [Public Profile API](https://developers.snap.com/marketing-api/Public-Profile-API/Introduction)، [Creator Discovery](https://developers.snap.com/marketing-api/Public-Profile-API/CreatorDiscovery)، [Get Started](https://developers.snap.com/marketing-api/Public-Profile-API/GetStarted)، [Profile Asset Management](https://developers.snap.com/marketing-api/Public-Profile-API/ProfileAssetManagement)، [تنزيل Snap من Memories](https://help.snapchat.com/hc/en-us/articles/7047492542484-How-do-I-download-a-Snap-from-Memories)، [My Data](https://help.snapchat.com/hc/en-us/articles/7012305371156-How-do-I-download-my-data-from-Snapchat)، [Embedding web content](https://developers.snap.com/api/snapchat-for-web/social-plugins/embedding-web-content)، [Terms](https://www.snap.com/terms).

### 4.3 LinkedIn

**ما تسمح به الوثائق:** Videos API توثق استرجاع video URN عبر `GET` وإرجاع `downloadUrl` لتنزيل/عرض أصل وسائط مخوّل. المثال الموثق نسخة MP4 مشتقة؛ لا يوجد ضمان أن الرابط يعيد الملف الأصلي غير المعالج، والرابط قد ينتهي أو يتوقف بسبب توقيعه. هذا ليس تنزيلًا عامًا لأي فيديو عام.

**الصلاحيات:** يتطلب الوصول اعتماد API وتفويض OAuth وصلاحيات مناسبة. قراءة منشورات العضو تتطلب `r_member_social` المقيدة، وتذكر الوثائق أن الطلبات الجديدة لها غير مفتوحة حاليًا. قراءة منشورات المؤسسة تتطلب `r_organization_social` ودورًا إداريًا أو ناشرًا مؤهلًا. Community Management API لها Development Tier محدود، وStandard Tier يتطلب موافقة، والاستخدام موثق للمؤسسات المسجلة والاستخدام التجاري.

**قرار المنتج:**

- لأرشفة محتوى حساب المستخدم أو صفحته: احتفظ بالملف الأصلي قبل رفعه.
- استخدم Videos API فقط بعد توافر الموافقة والصلاحيات ومعرّف فيديو مخوّل، وتعامل مع `downloadUrl` كرابط مؤقت لنسخة قد تكون معالجة.
- للمحتوى العام لطرف آخر: استخدم تضمين المنشور العام عندما يسمح المؤلف؛ التضمين ليس تنزيلًا.
- لا تستخدم scraping أو تتجاوز ضوابط الوصول أو تنسخ محتوى الآخرين دون إذن مالكه؛ اتفاقية المستخدم تقيد ذلك.

**التصنيف:** تنزيل رسمي محدود لمحتوى مخوّل؛ embed للمنشورات العامة؛ تنزيل عام من رابط المنشور يُرفض.

**مصادر:** [Videos API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/videos-api?view=li-lms-2026-09)، [Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api?view=li-lms-2026-09)، [Authentication](https://learn.microsoft.com/en-us/linkedin/shared/authentication/authentication?view=li-lms-2026-09)، [تضمين منشور](https://www.linkedin.com/help/linkedin/answer/a529065)، [Community Management overview](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/community-management-overview?view=li-lms-2026-09)، [User Agreement](https://www.linkedin.com/legal/user-agreement)، [Marketing API Terms](https://www.linkedin.com/legal/l/marketing-api-terms).

### 4.4 Vimeo

**ما تسمح به الوثائق:** Vimeo يوثق API لإرجاع روابط تشغيل وتنزيل حقيقية لملفات الفيديو عبر نقطة الفيديو، بتوكن مصادق يتضمن `public` و`private` و`video_files`، ولعضوية Standard أو أعلى (مع دعم خطة Pro القديمة). الوصول الخاص مرتبط بعضو مفوض. روابط التنزيل الناتجة صالحة 24 ساعة؛ بعد ذلك يجب إعادة جلبها من API. يجب استخدام روابط CDN كما وردت.

النسخ المحوّلة لا تضمن ملف الرفع الأصلي. حفظ المصدر الأصلي إعداد منفصل يتطلب خطة مدفوعة وتفعيله مقدمًا، ولا يعيد الملفات المحذوفة تلقائيًا. Vimeo API متاحة عمومًا دون رسوم، لكن ميزة ملفات الفيديو مقيدة بالخطة. من صفحة Vimeo، تنزيل الفيديو العام مشروط بإتاحة المالك للتنزيل وبحساب مسجل؛ المشاهد لا ينزّل من المشغل المضمّن. oEmbed يعيد بيانات وصفية وiframe، وليس ملف فيديو.

**قرار المنتج:**

- استخدم API لتنزيل محتوى تملكه أو لديك إذن واضح له، مع OAuth والحساب والخطة والنطاقات المطلوبة.
- عند طلب «الأصل»، فعّل تخزين المصدر قبل الرفع؛ لا تسمِّ النسخة المحوّلة أصلًا.
- خزّن رابطًا مؤقتًا قصير الأجل أو اجلبه عند الطلب، وأعد جلبه بعد انتهائه بدل الاحتفاظ به كحل دائم.
- استخدم زر صفحة الفيديو عندما سمح المالك بالتنزيل، وoEmbed/iframe للتضمين فقط.
- لا تتجاوز تسجيل الدخول أو CAPTCHA أو صلاحيات الفيديو أو قيود الخطة/API. تحذر Vimeo من أن أي شخص لديه direct file link قد يتمكن من التنزيل؛ لذلك يجب حماية هذا الرابط وعدم كشفه دون تفويض.

**التصنيف:** أفضل مسار رسمي للتنزيل المصرح به؛ embed/oEmbed للعرض؛ استخراج direct link من محتوى الغير أو خارج API يُرفض.

**مصادر:** [Video file links](https://developer.vimeo.com/api/files/video-links)، [Authentication](https://developer.vimeo.com/api/authentication)، [About API download links](https://help.vimeo.com/hc/en-us/articles/12427806914577-About-video-file-download-links-from-the-API)، [تنزيل فيديو](https://help.vimeo.com/hc/en-us/articles/12426502581265-How-to-download-a-video-on-Vimeo)، [Store source files](https://help.vimeo.com/hc/en-us/articles/46427284891537-Store-your-source-files-on-Vimeo)، [Direct links](https://help.vimeo.com/hc/en-us/articles/12426150952593-How-to-access-my-video-s-direct-links)، [oEmbed](https://developer.vimeo.com/api/oembed/videos)، [API prerequisites](https://help.vimeo.com/hc/en-us/articles/12427702473105-API-technical-and-developer-prerequisites)، [Terms](https://vimeo.com/legal/terms.md).

### 4.5 Twitch

**ما تسمح به الوثائق:** تنزيل VOD الخاص بصاحب القناة متاح من Video Producer بعد تفعيل تخزين البث، لكن Helix `Get Videos` توثق بيانات وصفية وروابط مشاهدة ولا توثق تنزيل ملف VOD كاملًا. مدد الاحتفاظ المذكورة: 7 أيام لمعظم القنوات، 14 يومًا للأفلييت، و60 يومًا للشركاء وTurbo وPrime. هذه المدد لا تمنح حق تنزيل محتوى الآخرين.

توجد نقطة API موثقة لتنزيل Clips، لكنها تتطلب `broadcaster_id` و`editor_id` وصفة محرر القناة، مع OAuth بنطاق `editor:manage:clips` أو `channel:manage:clips`، ولا يكفي أن يكون المقطع عامًا. الحد الأعلى 10 `clip_id` لكل طلب و100 طلب في الدقيقة، وروابط التنزيل مؤقتة وقد تنتهي.

**قرار المنتج:**

- لصاحب القناة: استخدم Video Producer لتنزيل تسجيلاته قبل انتهاء فترة الاحتفاظ.
- للـClips: نفّذ نقطة API الرسمية فقط بعد التحقق من محرر القناة والنطاقات، وتعامل مع الرابط كقصير العمر.
- للمحتوى العام: استخدم Twitch Player/iframe للعرض؛ لا تحاول استخراج ملف VOD أو تجاوز قيود الوصول.
- لا تعرض «تنزيل VOD» عامًّا ما لم توفر Twitch نقطة رسمية وصلاحية مناسبة.

**التصنيف:** تنزيل رسمي للـClips المخولة، وتنزيل صاحب القناة عبر Video Producer؛ embed للعرض؛ استخراج VOD العام غير الموثق يُرفض.

**مصادر:** [Videos API](https://dev.twitch.tv/docs/api/videos/)، [API reference](https://dev.twitch.tv/docs/api/reference)، [Video on Demand](https://help.twitch.tv/s/article/video-on-demand)، [Embedding video and clips](https://dev.twitch.tv/docs/embed/video-and-clips/)، [Clips API](https://dev.twitch.tv/docs/api/clips/)، [Authentication](https://dev.twitch.tv/docs/authentication/)، [Terms](https://www.twitch.tv/p/legal/terms-of-service/).

## 5. تصميم عملي لخدمة Vercel

### 5.1 حدود المنتج والواجهة

اقترح تقسيم المنتج إلى أوضاع واضحة بدل زر واحد اسمه «Download»:

- **استيراد ملف المستخدم:** يرفع المستخدم الملف الأصلي إلى التخزين الذي يختاره المشروع، مع بيان أن المصدر محفوظ قبل رفعه للمنصة.
- **تنزيل مصرح عبر API:** يظهر فقط بعد اختيار المنصة، إكمال OAuth، التحقق من الصلاحيات، والتحقق من أن المورد مخوّل.
- **عرض عبر المنصة:** يعيد embed/iframe/widget ولا ينشئ نسخة محلية.
- **غير مدعوم:** رسالة صريحة: «لا توثق المنصة تنزيل هذا المورد بهذه الطريقة؛ لا يمكن تنفيذ الاستخراج أو تجاوز القيود». 

يجب أن يوضح المنتج للمستخدم الفرق بين «رابط مشاهدة»، و«رابط ملف مؤقت»، و«ملف مصدر أصلي»، و«تضمين». لا ينبغي تسمية `downloadUrl` من LinkedIn أو Vimeo «ملفًا أصليًا» إلا إذا أكدت المنصة ذلك، وهي لا تؤكده في النتائج المقدمة.

### 5.2 تدفق طلب آمن

1. **تحليل الرابط دون تنزيل:** تحديد المنصة ونوع المورد (Pin، Profile asset، LinkedIn video، Vimeo video، Twitch Clip/VOD).
2. **تحديد الأهلية:** هل المورد يخص حساب المستخدم؟ هل لديه OAuth/دور/خطة/قائمة سماح؟ هل الخيار متاح رسميًا؟
3. **طلب التفويض:** استخدام OAuth الرسمي فقط، مع أقل scopes لازمة. لا تجمع كلمة مرور المنصة ولا تعتمد على جلسة متصفح.
4. **استدعاء endpoint الموثق:** استخدام معرف المورد والصلاحيات المطلوبة، والتحقق من استجابة المنصة بدل استنتاج رابط من HTML.
5. **التعامل مع الرابط المؤقت:** في Vimeo وLinkedIn وTwitch Clips، اجلب الرابط عند الحاجة، استخدمه ضمن صلاحيته، ولا تحوّله إلى رابط دائم أو تكشفه بلا حماية.
6. **الحدود وإعادة المحاولة:** احترم rate limits، وطبّق backoff، ولا تعيد المحاولة بلا حدود. في Twitch Clips مثلًا، لا تتجاوز 10 مقاطع للطلب و100 طلب/دقيقة. في Pinterest، راقب حدود Trial/Standard و`org_read`.
7. **التسليم أو التضمين:** إن كانت النتيجة ملفًا مصرحًا، سلّمها للمستخدم ضمن جلسة قصيرة. وإلا أعد embed رسميًا أو ارفض بأمان.
8. **السجل والتدقيق:** خزّن معرف المنصة، نوع المورد، نتيجة فحص الصلاحية، وقت جلب الرابط، وانتهاء الرابط، دون تخزين access tokens في السجلات.

### 5.3 اعتبارات Vercel

- اجعل وظائف Vercel serverless **طبقة تحقق وتنسيق** لا وكيلًا لتجاوز المنصة.
- خزّن أسرار OAuth في متغيرات بيئة خادمية، ولا تعرّضها للمتصفح. استخدم مخزنًا مشفرًا/مناسبًا للتوكنات بحسب بنية المشروع، مع تدويرها وإلغائها عند فصل المستخدم.
- لا تجعل Vercel وسيطًا دائمًا لملفات كبيرة أو روابط CDN مؤقتة؛ سلّم المستخدم أو التخزين المصرح له رابطًا قصير الأجل، مع مراعاة مدة الصلاحية والحجم. لا يثبت المصدر أن حدود التخزين أو مدد تنفيذ Vercel تسمح بأي حجم؛ لذلك ينبغي عدم إضافة وعد غير موثق حولها.
- افصل مفاتيح وموافقات كل منصة؛ فتوفر OAuth لمنصة لا يمنح صلاحية لمنصة أخرى.
- صمّم مسارًا بلا تنزيل (`embed`) حتى لا تحاول الخدمة الاحتفاظ بملفات لا تملك حق استضافتها.
- أظهر سياسة احتفاظ مختصرة: لا تخزن محتوى الطرف الثالث إلا بقدر ما يلزم للمسار المصرح، ولا تحفظ direct links أو الملفات أكثر من اللازم.

### 5.4 مصفوفة رفض ورسائل المستخدم

| الحالة | التصرف |
|---|---|
| رابط عام بلا تفويض ولا endpoint تنزيل موثق | رفض التنزيل، عرض embed إن كان رسميًا متاحًا |
| OAuth ناقص أو scope غير مناسب | اطلب التفويض الرسمي أو ارفض؛ لا تطلب scope أوسع بلا حاجة |
| حساب/مورد خاص دون عضوية أو دور مناسب | رفض، مع توضيح أن الخصوصية لا تُتجاوز |
| رابط مؤقت منتهي | إعادة جلبه من API إذا بقيت الصلاحية؛ وإلا اطلب إعادة التفويض |
| المنصة تتيح عرضًا فقط | عرض embed مع وسم «ليس تنزيلًا» |
| المستخدم يطلب scraping أو تجاوز CAPTCHA/تسجيل الدخول | رفض صريح |
| المستخدم يثبت ملكيته وendpoint الرسمي يعيد ملفًا | تنفيذ التنزيل ضمن scope والخطة والحدود الموثقة |
| API تعيد نسخة معالجة | تسميتها «نسخة متاحة من المنصة» لا «الملف الأصلي» |

## 6. الخلاصة

المنتج القابل للدفاع تقنيًا وقانونيًا هو **خدمة تنزيل مصرح ومحدود**، لا خدمة استخراج عامة. Vimeo هو أوضح مسار API لتنزيل ملفات لحساب/عضو مخوّل، مع روابط مدتها 24 ساعة وخطة ونطاقات مطلوبة. Twitch يتيح تنزيل Clips ضمن صلاحية محرر القناة، بينما VOD يخص مسار Video Producer لصاحب القناة. Snapchat يمكنه إعادة `media_url` لأصول Public Profile محددة بعد القائمة البيضاء وOAuth. LinkedIn يتيح `downloadUrl` لفيديو مخوّل، لا تنزيلًا عامًا. Pinterest لا توثق API لتنزيل MP4؛ تنزيلها المحدود من واجهة المنتج لا يحوّل API إلى أداة استخراج.

لذلك، أي طلب تنزيل لا يقع داخل مسار رسمي وصلاحية قابلة للتحقق يجب أن يتحول إلى **embed للعرض** أو **رفض مع توجيه المستخدم إلى خيار التنزيل الرسمي/طلب إذن من صاحب الحقوق**. هذا الحد ليس تفصيلًا واجهيًا؛ بل هو أساس بنية المشروع، وإدارة التوكنات، وتخزين الملفات، وتكاليف الطلبات، ورسائل المستخدم، وقابلية الخدمة للاستمرار عند تغير المنصات.
