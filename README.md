# نزّل — خدمة روابط الوسائط العامة

واجهة تنزيل بسيطة سوداء وخدمة API لاستخراج ملف تنزيل واحد من رابط عام في منصات محددة. YouTube يُعالَج عبر سلسلة مزودات Toshiro وVidSnap ومزودات احتياطية اختيارية؛ TikTok يُحلّ عبر Toshiro ثم `api.vidsnap.app` كاحتياط. تستخدم بقية المنصات `yt-dlp` بإعدادات مقيدة. لا تستخدم الخدمة cookies أو حسابات أو بروكسيات لإخفاء الحظر. **ليست كل الروابط أو المنصات قابلة للتنزيل**؛ إذا رفض المصدر الطلب فستظهر رسالة واضحة بدل تجاوز الرفض.

## تفسير 402 / 403 / 443

- `HTTP 402` رد من المنصة أو CDN؛ لا يستخدم المشروع API مدفوعًا، ولا يعني الرمز بحد ذاته أن Vercel يطلب دفعًا.
- `HTTP 403` رفض وصول من المصدر، قد يكون بسبب الخصوصية أو صلاحية تنزيل معطلة أو حجب خروج Vercel.
- `443` غالبًا منفذ HTTPS في رسالة TLS/اتصال، وليس حالة HTTP. لا يمكن معرفة سبب سجلات yy على الإنتاج دون صلاحية قراءة سجلات Vercel.

## نطاق الاستخدام

الـextractor يدعم الروابط العامة في: Facebook، Instagram، TikTok، Reddit، Dailymotion، SoundCloud، Flickr، وStreamable. TikTok له مسار مزودات مستقل (Toshiro ثم VidSnap)، بينما تستخدم المنصات الأخرى `yt-dlp`. دعم أي مزود لا يضمن نجاح كل فيديو؛ قد تتغير المنصات أو ترفض عنوان IP السحابي أو لا توفر ملفًا مباشرًا واحدًا. تنزيل المحتوى الخاص أو المقيد غير مدعوم.

**مواقع لا تُسحب آليًا في هذه النسخة:**

- X: قواعد X تحظر أتمتة موقع الويب خارج API الرسمية.
- Pinterest: API العامة لا توثق تنزيل ملف فيديو خامًا؛ التنزيل من واجهة المنتج فقط عندما يسمح صاحب Pin.
- Snapchat: روابط تنزيل الوسائط متاحة ضمن Public Profile API المقيدة بـOAuth وقائمة سماح.
- LinkedIn: يتطلب Video URN مخولًا وصلاحيات API المعتمدة.
- Vimeo: تنزيل API يحتاج فيديو مخولًا وtoken بنطاق `video_files`.
- Twitch: تنزيل Clips يحتاج OAuth ودور محرر القناة؛ تنزيل VOD يخص مالك القناة في Video Producer.
- Threads: لم يُدرج لعدم وجود مسار تنزيل مباشر موثق في API التضمين.

لا تعطي واجهات Meta وTikTok العامة التي راجعناها رابط ملف تنزيل: oEmbed يعيد HTML وبيانات لعرض/تضمين المحتوى. تعتمد خدمة TikTok هنا على مزودات تنزيل خارجية، وقد تظل بعض الروابط غير متاحة؛ لا نخلط embed مع التنزيل ولا نزعم أن المنشور العام يساوي إذنًا بالنسخ.

## ما الذي تغير

- فصلت المنصات والتحقق من DNS/SSRF وتصنيف الأخطاء والاستخراج والكاش ومسارات Flask إلى وحدات مستقلة.
- أضفت تمييزًا بين 402/403/429 وأخطاء TLS/HTTPS؛ logs لا تحتوي query أو رابط CDN الخام.
- رابط `/resolve` لا يعيد عنوان CDN أو صورة موقعة في JSON؛ التنزيل يمر عبر API ويدعم `Range`.
- أضفت توسعة محدودة للروابط المختصرة المعروفة مع فحص كل وجهة تحويل، ورفض YouTube وX والمنصات التي تتطلب تكامل API غير متوفر.
- الواجهة عربية RTL؛ الكاش وsingle-flight وحدود التزامن تقلل إعادة الاستخراج لكل نسخة Serverless.

## التطوير والاختبار

Python 3.12:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python app.py
```

افتح `http://localhost:8000`. الاختبارات:

```bash
python -m unittest discover -s tests -v
```

## النشر على Vercel

يحافظ المشروع على نقطة الدخول `app.py` (Flask WSGI) والواجهة الثابتة في `public/`. يعتمد على Python 3.12 و`requirements.txt`. `vercel.json` يفعّل Fluid Compute ومدة 300 ثانية. وثائق Vercel تدعم بث Python، وتذكر حد 300 ثانية لخطة Hobby عند Fluid Compute وحد حمولة 4.5 MB؛ اختبر ملفاتك الفعلية لأن البث لا يلغي حدود المدة/الاستجابة. للملفات الكبيرة جدًا، استخدم API رسميًا يعيد رابطًا مخولًا أو خدمة نقل/تخزين مناسبة.

متغيرات البيئة: `RATE_LIMIT_PER_MIN`, `DL_RATE_LIMIT_PER_MIN`, `BATCH_MAX`, `EXTRACT_TIMEOUT_SEC`, `MAX_PENDING_EXTRACTIONS`, `CACHE_TTL_SEC`, `CORS_ORIGIN`, `REDIRECT`. كاش ومحدد معدل الذاكرة لكل نسخة فقط؛ استخدم Vercel Firewall للحماية العالمية. تفاصيل API في [API.md](API.md)، ونتائج البحث الرسمية في [technical-research.md](research/technical-research.md) و[platforms-synthesis.md](research/platforms-synthesis.md).

استخدم الخدمة فقط للمحتوى الذي تملكه أو لديك إذن بتنزيله واحترم شروط المنصة وحقوق الناشر.

## الواجهة الجديدة وإصلاح 502 في YouTube

الصفحة الآن سبّورة بإطار خشبي (`public/img/board.jpg` و`wood.jpg`)؛ يمكنك استبدال `board.jpg` بصورة سبّورة حقيقية بنفس الاسم. فيها نافذة منبثقة للجودة والتقدم والأخطاء، وأيقونات SVG، وحركة قصيرة عند الفتح تحترم `prefers-reduced-motion`.

أسباب 502 التي عولجت:

1. المتصفح كان يستدعي روابط المزودين مباشرة، فتحجبها سياسة `connect-src 'self'` أو CORS أو ترفضها `api.vidsnap.app/proxy` بـ502/403. الآن يمر التنزيل عبر `/api/v1/youtube/download` على نفس النطاق.
2. فشل مزود واحد كان يعني فشل كل شيء؛ الآن المزودون يُجرَّبون بالتوازي مع فترة تهدئة، وإعادة محاولة تلقائية واحدة في الواجهة.
3. روابط المزودين تنتهي سريعًا؛ الخادم يعيد الاستخراج مرة واحدة ويختار الصيغة المطابقة.
4. الرسالة العامة أُبدلت بنافذة تعرض حالة كل مزود ورقم الطلب.
5. اسم الملف المحفوظ كان `download` بلا امتداد؛ يُقرأ الآن من `Content-Disposition`.

CSP في `vercel.json` سمحت الآن بـGoogle Fonts وصور `i.ytimg.com` والصور المحلية فقط. بدون إنترنت تعمل الصفحة بخطوط النظام. لا أستطيع من بيئتي الوصول إلى مزودي YouTube، لذا يجب اختبار الاستخراج الحي بعد النشر؛ إن بقي 502 فستظهر في النافذة حالة كل مزود لتعرف أيهم يفشل.
